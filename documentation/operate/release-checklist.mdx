## Hosted acceptance checks

<Steps>
  <Step title="Protected ledger">`GET /api/ledger` without a session → **401**.</Step>
  <Step title="Cross-origin writes">`POST` with a foreign `Origin` → **403**.</Step>
  <Step title="Sign-in">Wallet sign-in creates a workspace; signing in again reopens it. `/owner` works with the generated password.</Step>
  <Step title="Receiving wallet">Save it; reload; it persists.</Step>
  <Step title="Checkout privacy">In a signed-out browser, the checkout link works and shows no customer name or notes.</Step>
  <Step title="Historical rejection">An old transfer submitted against a new request → **422** and appears in Needs review.</Step>
  <Step title="Fresh payment">A fresh testnet transfer completes wallet → checkout → merchant workspace.</Step>
  <Step title="Cancellation">Cancel an awaiting request; checkout shows closed.</Step>
  <Step title="Persistence">State survives a restart/redeploy (same DB fingerprint in logs).</Step>
  <Step title="Backups">(SQLite) A backup restores into a separate test process.</Step>
  <Step title="Visual">Desktop dashboard and 390 px mobile checkout inspected.</Step>
</Steps>
