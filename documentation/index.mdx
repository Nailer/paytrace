**PayTrace** binds a merchant-issued USDC **payment request** to a public **checkout link** and to **finalized, canonical onchain evidence** on Monad Testnet. The payer transfers ERC-20 USDC directly from their own externally owned account (EOA) to the merchant's receiving address; a server-side verifier reads the transaction receipt through JSON-RPC, decodes the `Transfer` event log, checks chain ID, token contract, sender, recipient, exact integer amount, block canonicality and finality, and only then atomically claims that log as evidence and transitions the request to `received`. No custody, no smart contract, no token allowance.

<Accordion title="In plain English" icon="lightbulb">
PayTrace is like an invoice that checks itself. You (the seller) create a payment request that says *"Ada should send me exactly 25 USDC."* You send Ada a link. Ada pays from her own crypto wallet straight into yours, PayTrace never touches the money. Then PayTrace looks at the public blockchain record and confirms: the right person sent the right amount of the right coin to the right wallet, and the payment is permanent. Only then does it say **Received** and give both of you a receipt. No screenshots, no "did you get it?" messages.
</Accordion>

## The problem PayTrace solves

A blockchain transfer is a **context-free value movement**: it records that address A moved N base units of token T to address B in block K. It does not carry an invoice number, a customer identity or a statement of intent. Reconciling it against a receivable therefore requires an operator to manually confirm the token contract, the chain, the counterparties, the amount at full precision, the transaction's success status, its finality, and that the same transfer has not already been applied to another receivable.

<Accordion title="In plain English" icon="lightbulb">
When money lands in a crypto wallet, the blockchain only says "someone sent you some coins." It doesn't say *which invoice* that was for. So sellers end up checking by hand: Was it the real USDC or a fake token? Was it the full amount? Did it come from the right customer? Is it final? Did I already count this same payment for another invoice? That's slow and error-prone. PayTrace does all of those checks automatically, every time.
</Accordion>

  </Card>

<Warning>
PayTrace is an **initial multi-merchant testnet release**, not an audited production payments service. Test tokens have no monetary value. A finalized onchain receipt is **not** bank settlement, and cancelling a request does not reverse funds. See [Known limitations](/security/limitations).
</Warning>
