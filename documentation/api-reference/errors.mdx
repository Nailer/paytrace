## Format

```json
{ "error": "This transfer is already recorded. It cannot be counted twice." }
```

Messages are written for end users and are safe to display. Unexpected internal errors never leak details; they return a generic message with status 500.

## Status codes

| Status | Meaning in PayTrace |
| --- | --- |
| `200` | Success |
| `202` | Checkout verification pending (`{pending:true, summary}`): not yet available or not finalized |
| `400` | Invalid input (`LedgerError` default) or unknown action |
| `401` | Not signed in, session invalid, wrong password, bad signature, expired challenge |
| `403` | Origin, host or cross-site check failed; local-only workspace accessed remotely |
| `404` | Request, payment link or tracking token not found (or not in your workspace) |
| `409` | Conflict: not awaiting, already recorded, username taken, receiving wallet changed |
| `413` | Body too large |
| `415` | Not `application/json` |
| `422` | Evidence doesn't satisfy the request (creates a review item when matching) |
| `429` | Rate limited: ledger busy, verification busy, sign-in attempts, public RPC limited |
| `500` | Unexpected error (generic message) |
| `502` | RPC unavailable, wrong chain, inconsistent chain data (`VerificationError` default) |
| `503` | Server misconfiguration: missing origin, secret, password hash or hosted database |

<Accordion title="In plain English" icon="lightbulb">
- **2xx** = it worked (202 = "still waiting").
- **4xx** = something about the request was wrong (bad input, not logged in, wrong payment).
- **5xx** = PayTrace or the blockchain service had a problem; try again later.
</Accordion>
