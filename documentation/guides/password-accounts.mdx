Before wallet sign-in, merchants registered with a username and password. Those accounts remain fully supported.

## Sign in

Go to [`/password-login`](https://paytrace-tau.vercel.app/password-login), enter your username and password.

| Rule | Value |
| --- | --- |
| Username | 3–30 chars: lowercase letters, digits, `_`, `-`; must start with a letter or digit (case-insensitive input, stored lowercase) |
| Password | 12–128 chars at signup/reset |
| Hashing | `scrypt`, 64-byte key, 16-byte random hex salt, stored as `salt:hash` |
| Comparison | `timingSafeEqual` |
| Unknown usernames | Still perform a dummy hash check, then return the same error: *"Username or password is incorrect."* (prevents username enumeration by timing) |

<Accordion title="In plain English" icon="lightbulb">
Your password is never stored, only a scrambled fingerprint of it that can't be reversed. PayTrace also responds the same way whether a username exists or not, so attackers can't use it to discover usernames.
</Accordion>

## Recover access

There is **no email recovery**. You received a **recovery code** (32 random bytes, base64url) at signup.

<Steps>
  <Step title="Open /recover">From `/password-login`, click **Forgot password?**</Step>
  <Step title="Enter details">Username, recovery code, and a new password (twice).</Step>
  <Step title="Save the new recovery code">
    On success you get a **new** recovery code (download it as `paytrace-recovery.txt`). The old code stops working, the account `version` increments, and **all existing sessions are signed out**.
  </Step>
</Steps>

Recovery codes are stored only as SHA-256 hashes. The reset uses a conditional `UPDATE … WHERE id=? AND recovery=?`, so a code can be used exactly once even under concurrent attempts.

## Original owner workspace

[`/owner`](https://paytrace-tau.vercel.app/owner) signs into the **legacy** workspace with the deployment-wide password whose hash is `PAYTRACE_PASSWORD_HASH`. Owner sessions carry no account ID. Rotating that password also requires rotating `PAYTRACE_SESSION_SECRET` to revoke existing owner sessions, which signs **everyone** out.

## Migration

Wallet sign-in does **not** link or migrate password accounts or the legacy workspace. Existing records stay where they are.
